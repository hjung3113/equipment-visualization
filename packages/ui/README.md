# @eqv/ui

EV components for UI patterns that `@ap/ui` does not provide (ADR-0008, amended 2026-10-18).

**The rule:** a screen never restyles such a pattern itself. It gets a component here first, built only from `@ap/ui` primitives and theme utilities (no raw colours, no arbitrary values, no inline styles; the design lint checks `src/**/*.tsx`). Screens use these components without adding colour or typography classes; `core` and `renderer` must not import this package.

The package is consumed as TypeScript source (`exports` → `src/`). The host imports `@eqv/ui/styles.css` after the `@ap/ui` theme so Tailwind scans these components (Studio: `apps/studio/src/studio.css`). `@eqv/ui/theme.css` is the single owner of the `--eqv-*` → platform-token mapping; the Studio and the adapter's `styles.css` both import it. `@ap/ui` and `react` are peer dependencies. Words are the consumer's; this package owns none.

## Components

- `DataTable` — dense table in the AP `PlatformDataTable` frame (32px rows and header, sticky uppercase header, vertically centred cells, row borders on the cells). Props: `label` (accessible name, also names the scroll region), `columns` (header texts, or `{ id; header; align?; sortable?; className? }` — `className` is layout classes for the header cell; `<th scope="col">`), `children` (`DataTable.Row`s); other `<table>` attributes (for example `role="grid"`) pass through. Opt-in: `title`/`subtitle`/`actions`/`headingLevel` (title bar, default `h2`), `count` (status line), `state` (a `StateMessage`/`LoadingBlock` below the table, inside the frame), `capped` (60vh scroll viewport), `rows` (see below), `sort` + `onSortChange` (controlled, two-state: the sorted column flips, another column starts `ascending`; `aria-sort` on the `th`). The consumer sorts its own rows.
  - Virtual rows — `rows={{ count, render, estimateSize?, getKey?, initialIndex?, scrollToIndex?, scrollKey? }}` replaces `children` for tables that can hold thousands of rows (`@tanstack/react-virtual`, as AP's `PlatformDataTable`). It implies `capped`; the region is the scroll element. `render(index, rendered)` returns one `DataTable.Row` (the table adds `key`, `data-index`, `aria-rowindex` and the measuring `ref`; rows may differ in height) and gets `rendered`, the inclusive `{ start, end }` index window currently in the DOM, for a roving tab stop. From `VIRTUAL_ROW_THRESHOLD` (200) rows up, only the visible rows plus overscan render between two `aria-hidden` spacer rows, `aria-rowcount` is rows + 1 and `aria-rowindex` is index + 2 (the header is row 1); below it every row renders as plain DOM. `initialIndex` is the first position on mount (centred); `scrollToIndex` brings a row into the table's own viewport whenever the value changes (a no-op while it is visible; the page never scrolls); `scrollKey` repeats that scroll for an unchanged index (a repeated Home/End). A table that grows past the threshold keeps the scroll position it had. Rows not in the DOM cannot hold focus: a consumer that moves focus by keyboard scrolls first (`scrollToIndex`) and focuses the row when it mounts. In jsdom the virtualizer sees a 0-size region and renders no row; tests mock `HTMLElement.prototype.offsetHeight/offsetWidth` (see `test/data-table-virtual.test.tsx`). `style` is set only for spacer heights (the one lint exception, `eslint.config.js`).
  - `DataTable.Row` — `onActivate?` makes the row focusable and fires on click, Enter and Space; `selected?` sets `aria-selected` and shows the 2px accent bar. Arrow-key roving focus stays with the consumer (pass `tabIndex` and `onKeyDown`).
  - `DataTable.Cell` — `<td>`, or `<th scope="row">` with `rowHeader`; `numeric` (right-aligned tabular figures) and `mono`; `action` removes vertical padding for 32 px toolbar buttons and adds `data-action`; `colSpan` etc. pass through.
- `Panel` — framed section: `title?`, `subtitle?`, `actions?`, `headingLevel?` (2 or 3), `className?` (layout), `children`. With a title it is a `region` named by the heading.
- `StateMessage` / `LoadingBlock` — AP `StateView`. `StateMessage`: `tone?` (`neutral | warning | danger`; `danger` is `role="alert"`, the others `status`), `icon` (a lucide component), `title`, `body?`, `action?`, `compact?`. `LoadingBlock`: `label` (announced), `rows?` (default 3).
- `DetailFields` — `{ key; label; value; mono? }` rows on `@ap/ui` `FieldList` + `FieldRow` (`dl`/`dt`/`dd`); long labels and values wrap inside their column.
- `FileButton` — toolbar button that opens the file picker. Props: `label` (names the button and the hidden input), `accept?`, `disabled?`, `aria-describedby?` (on the visible button), `onFile(file)`, `icon?` (default `Upload`). Picking the same file twice fires twice.
- `FormField` — one labelled form control: `label`, `required?` (the `*` is `aria-hidden`), `hint?`, `error?` and `children: (control) => ReactNode`. Spread `control` (`id`, `aria-describedby`, `aria-invalid`, `aria-required`) onto the `@ap/ui` `Input`. `aria-describedby` lists the error id, then the hint id, each only while its text exists; `aria-invalid` is set only with an error. No `role="alert"`: the host moves focus to the first invalid field, which reads its description.
- `OutlineBadge` — the outline pill the platform design system no longer exports (AP ADR-0050): `@ap/ui` `Badge` with `variant="outline"`; other `Badge` props pass through (ADR-0013). Not a status (`StatusBadge`) and never an evidence level (`EvidenceBadge`).
- `EvidenceBadge` — `level: EvidenceLevel` (`observed | derived | illustrative | unknown`) and `children` (the label). The level shows without colour: always its text, plus a distinct border style per level (solid, dashed, dotted + italic, double). `illustrative` never looks like `observed` (ADR-0003). The level is exposed as `data-evidence` on the badge.
- `Legend` — `label` (accessible name of the list) and `items: { swatch: ReactNode; label: ReactNode }[]`; `swatch` is the consumer's (for example an SVG pattern) or `null` for a text-only row.
- `AppFrame` — app shell in AP ADR-0011 structure: brand rail, collapsible sidebar (head with the app name and a collapse toggle, `nav` of items), skip link and a focusable `main#eqv-main`. Props: `appName`, `brand` (rail mark letters, decorative), `items: { key; label; icon; href; current }[]` (`current` → `aria-current="page"`; collapsed items keep their name via `aria-label` and a tooltip), `linkComponent?` (the router link, default `a`), `labels: { nav; skipToContent; collapse; expand }`, `children`. Adds no heading. Collapse state persists when `collapsedStorageKey` is given; there is no shortcut yet.
- `ViewerZoomControls` — the Top View zoom controls for the renderer's `renderControls` slot: a `role="group"` of three `@ap/ui` toolbar `Button`s with leading `ZoomIn`/`ZoomOut`/`Maximize2` icons. Props: `controls` (`zoomIn`/`zoomOut`/`fit` actions and `canZoomIn`/`canZoomOut`/`canFit`; the same shape as the renderer's `TopViewerControls`, declared locally because this package never imports `@eqv/renderer`), `labels: { zoomIn; zoomOut; fit }`. A button is natively disabled when its capability is false.
- `Tabs` / `TabsList` / `TabsTrigger` / `TabsContent` — AP underline tabs: the `@ap/ui` tabs (same roles, selection and keyboard) with the platform's selection bar; a string trigger label reserves its bold width.
- `Page` — page head over the padded body. Props: `title?` (the page `h1`; without it only the body renders, for content that owns its heading), `description?`, `actions?` (right side of the head), `breadcrumb?` (`{ label; items: { key; label; href? }[] }`: ancestor crumbs in a `nav` named by `label`, before the `h1`; `href` crumbs render through `linkComponent?`, default `a`), `children`. Works without `AppFrame`.

## Not here

Status badge and toasts are `@ap/ui` parts, not EV components: `StatusBadge` (`tone`, `dot?`; never an evidence level, `EvidenceBadge` is the only evidence presentation) and `Toaster` (mounted once by the host) with `toast`.

## Conventions

- Toolbar buttons are `@ap/ui` `Button variant="secondary" size="toolbar"` with a `size-3.5` lucide icon before the label; the primary action is `variant="primary"`.
- AP typography maps to theme classes (no new utilities): card title `text-base leading-5 font-semibold`; table header `text-xs font-semibold uppercase tracking-wide`; mono `font-mono text-xs`; tabular figures `tabular-nums`; badge `text-tiny font-semibold`.
- Soft tints are `bg-accent-{success,warn,danger,primary}/12`; the neutral tint is `bg-surface-card-elevated`.
